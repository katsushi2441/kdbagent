# Kurage DB Agent — 安全のしくみと運用の注意

DBを直接いじれる道具は、便利さと危険が背中合わせです。この製品が
何を守り、何は守らないのかを、正直に書きます。

## この製品が守ること

### 1. 宣言した範囲しか触れない

見せる表・列・操作は `kdbagent_config.php` で宣言します。宣言外は、
ブラウザ・コマンド・APIのどれからも実行できません。

- 表名・列名は、SQLに組み立てる前に**必ず宣言済みリストと照合**します。
  利用者が送ってきた文字列を、そのままテーブル名や列名にしません。
- 更新・追加で `editable` にない列を指定しても、黙って捨てます。
- `can_insert / can_update / can_delete` が false の操作は通しません。

### 2. SQLインジェクションを通さない

すべてのSQLは **PDOのプリペアドステートメント**で、値は必ずbindします。
検索語に `'; DROP TABLE ...` のような文字列を入れても、それは
「ただの検索語」として扱われ、DBは壊れません（付属のテストで確認して
います）。

### 3. 認証と記録

- ブラウザの管理画面は**パスワード認証**（`password_hash`）。書き込みは
  **CSRFトークン**必須。
- HTTP API は**トークン**必須（設定でトークンが空なら、HTTP APIは無効）。
- 変更はすべて**監査ログ**に残ります（日時・実行者・表・行・変更内容・IP）。

## この製品が守らないこと（利用者の責任）

- **設定に何を宣言するかは、あなたの責任です。** `editable` に
  パスワード列や金額列を入れれば、それは編集できてしまいます。見せて
  よい・直してよい列だけを宣言してください。
- **サーバーのファイル保護はあなたの責任です。** `kdbagent_config.php`
  （接続情報＝DBのパスワードを含む）や `kdba_data/`（sqlite本体・監査
  ログ）を、Webから直接ダウンロードされないようにしてください。付属の
  `.htaccess` はこれを行いますが、お使いのサーバーで有効か確認して
  ください。
- **鍵なし運用（`KDBA_PASSWORD_HASH` が空）は、閉じた環境だけにして
  ください。** 公開サーバーで鍵なしは、宣言した範囲とはいえ誰でも
  編集できてしまいます。

## 設置チェックリスト

- [ ] `kdbagent_config.php` を作り、`KDBA_PASSWORD_HASH` を設定した
- [ ] `kdba_data/` と `kdbagent_config.php` がブラウザで開けないことを確認した
      （`https://.../kdba_data/app.sqlite` が 403/404 になるか）
- [ ] `editable` に、見せてよい・直してよい列だけを宣言した
- [ ] HTTP API を使うなら `KDBA_API_TOKEN` を十分に長い値にした
- [ ] 監査ログ（`KDBA_AUDIT_LOG`）の置き場所を決めた

## AIエージェントに使わせるときの考え方

Claude Code などにこのツールを使わせるのは、**範囲が絞ってあるからこそ
安全**です。「顧客の電話番号だけ直して」と任せても、`editable` に
`phone` しか入れていなければ、それ以外は直せません。エージェントに
渡す前に、**設定で範囲を絞る**ことが、そのまま安全策になります。
